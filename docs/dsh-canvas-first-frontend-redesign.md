# DSH 任务书：重做 AI Image Hub 的 LibTV 风格画布前端

## 0. 任务目标

把 AI Image Hub 从“左侧生成表单 + 右侧固定侧栏/任务列表”的工作台，重做为**LibTV 类似的、画布优先的节点连线创作界面**。

用户的明确目标：

- 全程保持一个干净的无限画布；
- 取消固定的提示词生图侧边栏；
- 提示词、参考图、模型参数、生成结果都以可操作的节点或浮动上下文界面存在；
- 画布上的节点和连线能够表达“参考素材 → 生成请求 → 生成结果 → 再次派生”的关系；
- 不要做成技术工作流编排器，不暴露 ComfyUI 式底层节点；这是给设计人员用的视觉创作画布；
- 保留现有项目隔离、历史、权限、任务与存储的后端能力。

视觉参考方向：LibTV / Lovart 式的干净创作画布。核心不是复制品牌 UI，而是使用其交互范式：**画布是主界面，工具和配置按需出现，界面不长期占用大块固定区域。**

├── 生成节点（提示词 + 模型/参数 + 生成按钮）
├── 结果节点（任务状态 / 生成图 / 元数据）
├── 备注节点（轻量文本）
└── 分组框节点（可选，但推荐）

按需出现的轻量 UI
├── 小型工具条：上传、创建生成节点、创建备注、适应画布、撤销/重做（如实现）
├── 选中节点后的上下文操作浮层
├── 生成节点展开时的参数区域
├── 任务状态小卡/顶部轻量提示

### 核心原则

- **不能有右侧固定提示词生图侧边栏。**
- 不能有一个长期占据三分之一屏幕宽度的固定参数面板。
- 生成配置只在以下场景出现：
  - 画布上的生成节点处于编辑/展开状态；
  - 用户点击“新建生成节点”；
  - 用户从某个结果“继续生成/再次使用”。
- 未操作时，用户看到的应主要是画布、素材、结果和关系，而非表单。

## 4. 节点模型与连线语义

第一版至少实现以下节点类型。

| 节点 | 职责 | 数据来源/持久化 | 连线语义 |
|---|---|---|---|
| `reference_image` | 已上传的参考素材 | 画布状态；真正提交仍通过现有 references 上传接口 | 指向生成节点，表示其作为输入参考 |
| `generation_request` | 用户可编辑的提示词、模型与参数，承担提交动作 | 画布状态中的草稿节点；提交后生成不可变任务 | 入边来自参考节点/结果节点，出边到生成结果 |
| `generation_result` | 一个不可变 generation 任务的可视化代理 | 现有 Generation/Artifact/Reference 数据；只保存节点位置等 UI 状态 | 入边来自请求节点及其输入，表示谱系 |
| `note` | 创作备注或从提示词创建的可编辑文本 | 画布状态 | 无业务含义，可自由摆放；可选关联到结果 |
| `frame`（推荐） | 概念、方案、分支或阶段的视觉分组 | 画布状态 | 不作为生成输入；仅视觉归类 |

### 连线要求

- 连线表示**派生关系与输入关系**，不是需要用户手动接端口的技术流程图；
- 参考素材或结果被加入某个生成节点的输入后，自动出现其到生成节点的虚线/细线；
- 提交生成后，立即在生成节点附近创建一个或多个 `generation_result` 处理中节点，并连线；
- 任务完成时，同一结果节点原地更新为图片，不改变位置；
- 从已有结果继续生成时，应生成新的 `generation_request` 或将结果作为输入挂到新请求，新的结果连线从该请求出发；
- 移动/删除画布节点仅影响画布表现，**不得删除或改写底层 Generation、Artifact、历史记录。**

### 参考图顺序（严格）

参考图是执行合约，不能从画布位置推断顺序。

- 生成节点内部显示显式顺序：`图 1 / 图 2 / 图 3…`；
- 拖动画布节点不改变参考输入顺序；
- 参考顺序必须能通过生成节点的缩略图区域拖拽排序，或明确的上移/下移操作调整；
- 画布节点上的编号、生成节点内的输入缩略图、实际 API 提交顺序必须一致；
- 历史任务保留当时冻结的参考顺序，不受后续画布调整影响。

## 5. 生成节点详细要求

生成节点是本次重做的关键。

### 默认形态

- 紧凑卡片，显示：标题、提示词摘要、已绑定参考图数量、模型摘要、状态；
- 画布上可随意拖动；
- 初次创建时处于展开编辑状态；
- 失焦/提交后可折叠为紧凑形态；
- 单击已存在节点可以再次展开编辑；
- 不要自动把每个生成节点长期展开，避免画布变成表单墙。

### 展开编辑形态

展开时包含：

```text
提示词 textarea（足够大，可垂直调整）
已绑定参考图缩略图和顺序
平台
模型
画面比例
分辨率
质量档位 / 生成数量（仅选中模型支持时显示）
生成按钮
```

要求：

- 模型控件必须由当前后端提供的 capability/profile 数据驱动；
- 不支持的参数不得显示或不得提交；
- 切换模型时保留兼容值，不能静默乱重置；
- 提交时继续使用现有 `idempotency_key` 和项目级 API；
- 生成过程显示明确状态：校验中、排队中、生成中、成功、失败、需恢复；
- 失败且可安全重试的任务显示重试；外部已提交任务不得显示盲目重试；
- 一个请求支持 1–4 张时，必须显示独立结果节点和独立历史记录，而不是一张模糊的批任务图。

## 6. 关键交互契约

### 6.1 画布导航

- 空白处按住拖动：平移画布；
- 鼠标滚轮/触控板：围绕指针缩放；
- 缩放范围合理，例如 25%–250%；
- 提供“适应内容”按钮；
- 提供轻量缩放显示与 `- / 100% / +` 控件；
- 必须支持白色背景 + 浅灰点阵，且点阵随画布平移对齐；
- 不得出现页面横向溢出。

### 6.2 选择、拖拽与检查状态

这三种状态必须分离：

```text
focusedNodeIds     临时选中，用于移动/删除/分组
inspectedNodeId    当前被打开查看、复用参数的一个结果
referenceOrder     下次生成的有序输入参考
```

具体行为：

- 单击节点：选中；
- 单击成功结果：可进入检查/复用状态，临时载入它的不可变参数；
- 拖拽节点：改变节点位置，不改变参考顺序；
- 拖动空白画布：保持当前选中和检查状态，不能取消选中；
- 单击空白处（没有拖动）：可清空临时选中，或退出检查并恢复原草稿；
- 进入明确的“选择参考”模式后，只有 `Shift + 点击` 才增删参考素材；普通点击不能意外修改参考输入；
- 删除节点需只删除画布节点；已有结果的底层历史和图片不可删除。

### 6.3 上传与放置

- 点击上传或把图片文件拖入画布，都创建 `reference_image` 节点；
- 拖入多个文件时生成多个节点，并相对放在投放点附近；
- 保持图片原始比例，不拉伸；
- 支持多次追加上传；
- 与现有格式/大小校验规则一致。

### 6.4 审图

- 双击结果或点击明确的预览动作，打开全屏审图；
- 保持图像原始比例，不能裁切或拉伸；
- 支持缩放、鼠标/触控拖动画面、重置、上一张/下一张、Esc 关闭、下载原图；
- 显示提示词、平台、模型、比例、分辨率等元数据；
- 历史页面也必须能打开同一个审图体验。

### 6.5 历史与画布定位

- History 是不可变任务证据的浏览页，保留搜索、筛选、满意/采用/不满意、下载、再次使用；
- 从历史点击“定位到画布”：切回画布，居中并选中对应结果节点；
- 从历史点击“再次使用”：创建或打开一个新的生成节点，载入历史参数，不能改写原任务；
- 画布节点和 History 只是在展示同一生成证据，不能产生两套不同真相。

## 7. 视觉与界面规则

### 视觉方向

- 视觉风格：内部专业创作工具，干净、克制、内容优先；
- 画布：纯白背景、浅灰点阵；
- UI 主色：黑白灰；绿色只作极少状态点缀，红色仅用于错误/危险动作；
- 不使用荧光黄绿、重紫色大面积背景或花哨渐变；
- 节点使用低阴影、清晰边界、适度圆角；
- 画布中的图片与结果优先，控件退后；
- 任何固定 UI 不得遮挡关键视觉内容。

### 字体

沿用当前本地优先字体原则，不依赖公网字体：

```css
Inter, PingFang SC, Microsoft YaHei, system-ui, sans-serif
```

可在不引入外部 CDN 的前提下改善字重、字号、行高和层级。

### 顶栏

- 顶栏可弱化或画布模式下自动隐藏为顶部感应条；
- 鼠标靠近顶部、键盘焦点进入导航、或用户显式点击时展开；
- 移动端不得依赖 hover；
- 管理入口仍只对管理员显示；
- 顶栏不应长期抢占画布空间。

### 禁止项

- 不要固定右侧生成面板；
- 不要把生成参数常驻在画布之外；
- 不要使用 emoji 作为主要结构图标；
- 不要把结果压缩成只看得见小缩略图的状态队列；
- 不要让按钮覆盖结果图片的核心视觉区域；
- 不要把节点连线做成复杂技术拓扑。

## 8. 画布状态持久化

画布状态通过现有 API 持久化：

```text
GET/PUT /api/projects/{project_id}/canvas
```

建议保存的状态形状（可扩展，但必须兼容已有草稿字段）：

```json
{
  "viewport": {"x": 0, "y": 0, "zoom": 1},
  "nodes": [
    {
      "id": "local-ui-id",
      "kind": "reference_image | generation_request | generation_result | note | frame",
      "x": 320,
      "y": 180,
      "width": 300,
      "height": 220,
      "generation_id": "optional-existing-generation-id",
      "reference_ids": ["ordered-reference-node-id"],
      "ui": {}
    }
  ],
  "edges": [
    {"id": "edge-id", "from": "node-id", "to": "node-id", "kind": "input | result"}
  ],
  "draft": {
    "prompt": "...",
    "provider": "...",
    "profile": "...",
    "ratio": "...",
    "resolution": "...",
    "quality": "..."
  }
}
```

要求：

- 使用 debounce 自动保存，不要每一次 pointermove 都发请求；
- 保存中/已保存/保存失败要有轻量可见反馈；
- 保存节点位置、缩放与草稿时，不能互相覆盖字段；
- 不能让前端画布状态替代数据库里的不可变 generation evidence；
- 历史 generation 载入时，如果没有画布节点，可按合理位置创建展示节点；
- 旧项目无画布状态时应正常打开，不报错。

## 11. 验收场景（必须浏览器实测）

### A. 基础画布

1. 打开项目工作台，初始看到干净画布，没有固定右侧生成侧栏；
2. 画布是白色背景 + 浅灰点阵；
3. 空白拖动可平移，滚轮缩放围绕指针发生；
4. 适应画布按钮将节点都纳入可视区域；
5. 页面没有横向溢出。

### B. 节点与连线

1. 上传两张图片，画布出现两个比例正确的参考图节点；
2. 创建生成节点，绑定两张参考图，显示 `图 1 / 图 2`；
3. 参考节点 → 生成节点出现输入连线；
4. 调整参考顺序后，节点编号、生成节点缩略图编号和提交顺序一致；
5. 提交生成后，生成节点附近出现处理中结果节点和请求→结果连线；
6. 完成后结果节点原地显示图片；
7. 移动节点，连线跟随更新。

### C. 选中与拖拽

1. 单击生成结果进入检查状态；
2. 拖动空白画布，检查状态和选中状态保持；
3. 单击空白画布，才退出检查并恢复原草稿；
4. 拖动节点不改变参考顺序；
5. 只有显式参考选择模式 + Shift 点击才改变参考集合。

### D. 参数与历史

1. 展开生成节点，提示词框足够大且可继续调整；
2. 模型参数根据 capability 动态出现；
3. 任务完成后历史中出现同一 generation；
4. 从历史“定位到画布”能聚焦正确节点；
5. 再次使用创建新的请求/结果，不覆盖旧记录。

### E. 审图

1. 打开结果审图，图片比例正确；
2. 放大、拖动、重置、上一张/下一张、Esc 和下载都可用；
3. 关闭后页面滚动与画布状态正常。

### F. 权限与 Demo

1. 普通用户无管理入口，直访管理页仍 403；
